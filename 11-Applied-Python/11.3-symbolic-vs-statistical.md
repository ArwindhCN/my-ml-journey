## The core idea in one line

**Rules first for what's certain, statistics only for the residual, rules again
to gate the output — statistical methods sit in the middle, never at the
boundary and never at the decision.**

---

## 1. The two paradigms

```
  SYMBOLIC AI                        STATISTICAL AI
  ───────────                        ──────────────
  knowledge is WRITTEN               knowledge is FITTED
  by a human expert                  from a dataset

  if egfr < 60: risk                 w₁·egfr + w₂·age + b → 0.87

  Ch 11.2 rule engine                Ch 1–10 everything
  Ch 12 Neo4j facts                  Ch 13 CNNs, Ch 14 GNNs
```

These were rival camps, not complementary tools. Symbolic AI dominated from the
1960s to the 1980s — **MYCIN**, an expert system that diagnosed blood infections
from roughly 600 hand-written rules, outperformed junior doctors. Then the field
collapsed into the **AI winter** and statistical methods took over entirely.

**MYCIN worked.** It was accurate and fully explainable. Hospitals still didn't
deploy it.

---

## 2. Why symbolic AI collapsed — the knowledge acquisition bottleneck

MYCIN's 600 rules were written by Stanford infectious-disease experts over
several years.

> **Knowledge acquisition bottleneck:** every rule costs expert hours, and
> experts are the scarcest resource in the system. Medicine publishes thousands
> of papers a week. A rule base grows at the speed of a committee.

### ❌ The overcorrection I reached for

> *"We must develop a product which would learn automatically and get updated."*

Intuitive, and wrong for this system. Apply it to BioPrecision-AI:

```
  Monday    eGFR threshold = 60    (KDIGO)
  Thursday  model retrains on new data
  Friday    effective threshold ≈ 54
              ▲
              └── Who approved that? What do you cite when
                  a clinician asks why the alert stopped firing?
```

That trades away **contestability** — the exact property 11.2 established as the
reason the alert carries an `evidence` field. And since the update came from
data, whatever bias is in the data is now in the clinical threshold, silently,
with no changelog.

### The bottleneck doesn't vanish — it relocates

```
  SYMBOLIC bottleneck      experts write rules
  STATISTICAL bottleneck   experts label data
                            ▲
                            └── still expert hours. Often MORE of them.
                                600 rules vs 50,000 labelled cases.
```

A labelled clinical dataset **is** expert judgement — anonymised, atomised, and
stripped of its reasoning. You don't escape needing experts. You escape being
able to *read* what they knew.

### ✅ The actual resolution: separate facts from judgement

```
  DDI facts        → 178k edges, updated from DrugBank releases,
                     ingested by ETL, not typed by hand           ← scales
  Decision logic   → ~10 rules, changes rarely, each one cited    ← doesn't need to scale
```

**The rules don't scale, but they don't have to.** BioPrecision-AI has a handful
of decision rules over a knowledge base of 178,000 edges. The part that grows is
*data ingestion* (Ch 12.7, `ingest_ddi.py`). The part that stays small is
*judgement*.

**MYCIN's real mistake:** it put the facts *inside* the rules. 600 rules because
each hardcoded a specific organism. Separate the two and the bottleneck largely
dissolves.

> The instinct that BioPrecision-AI has a long-term weakness is still correct —
> it can only know what someone has ingested. That's the coverage gap from 11.2,
> and it's the hole Ch 14.8 link prediction targets.

---

## 3. The decision framework

| Ask | Symbolic | Statistical |
|---|---|---|
| Can a human write the rule down? | yes → | no → |
| Cost of a wrong answer | severe / irreversible | tolerable |
| Must the answer be contestable? | yes → | no → |
| How many training examples exist? | few or none | many |
| Does the pattern shift over time? | stable | drifting |

Read it as a checklist, not a scoreboard. **A single "severe / irreversible" in
row 2 outweighs several statistical votes elsewhere.**

## 4. Worked case — messy drug-name resolution

The EHR exports free-text medication names. Each must map to a canonical drug
node in Neo4j:

```
  "Warfarin"                    "warfarin sod. 5mg"
  "WARFARIN SODIUM"             "Warf 5"
  "Metformin HCl 500mg"         "Atorvastatin Calcium 20 mg"
```

### ❌ My first architecture — right answer, wrong order

> *"Since it is new data we must use embedding, that is statistical, and we can
> also use some hardcoded rules to classify the output."*

Hybrid is correct. But this puts **statistics first and rules second as a
cleanup layer**, and it should run the other way. Walk the table:

```
  "WARFARIN SODIUM"   →  lowercase, strip salt suffix  →  "warfarin"
  "warfarin sod. 5mg" →  expand abbrev, strip dose     →  "warfarin"
  "Warf 5"            →  ??? no rule covers this
```

The first two are **deterministic string transforms**. A human writes that rule
in five minutes; it is exact and costs nothing to run. Running an embedding
model on `"WARFARIN SODIUM"` spends a probabilistic method on a solved problem —
and introduces a chance of being wrong where **zero** chance existed.

Only `"Warf 5"` genuinely needs fuzzy matching.

### ✅ The correct architecture

```
  raw string
      │
      ▼
  ┌─────────────────────────────────────────┐
  │  1. RULES: normalise + exact lookup     │  ← handles most cases, exact, free
  └─────────────────────────────────────────┘
      │ no match
      ▼
  ┌─────────────────────────────────────────┐
  │  2. STATISTICAL: fuzzy / embedding      │  ← handles only the residual
  │     match against canonical drug names  │
  └─────────────────────────────────────────┘
      │ returns candidate + confidence
      ▼
  ┌─────────────────────────────────────────┐
  │  3. RULES: confidence gate              │
  │     ≥ 0.95 → accept                     │
  │     < 0.95 → QUEUE FOR HUMAN REVIEW     │  ← never auto-accept
  └─────────────────────────────────────────┘
```

**Verified output:**

```
Warfarin                     -> norm=warfarin      exact_rule  conf=1.0    ACCEPT        warfarin
WARFARIN SODIUM              -> norm=warfarin      exact_rule  conf=1.0    ACCEPT        warfarin
warfarin sod. 5mg            -> norm=warfarin      exact_rule  conf=1.0    ACCEPT        warfarin
Warf 5                       -> norm=warf          fuzzy       conf=0.667  HUMAN_REVIEW  None
Metformin HCl 500mg          -> norm=metformin     exact_rule  conf=1.0    ACCEPT        metformin
aspirin 75                   -> norm=aspirin       exact_rule  conf=1.0    ACCEPT        aspirin
Atorvastatin Calcium 20 mg   -> norm=atorvastatin  exact_rule  conf=1.0    ACCEPT        atorvastatin
Zolpidem                     -> norm=zolpidem      fuzzy       conf=0.0    HUMAN_REVIEW  None

stage-1 (rules only) coverage: 6/8
```

Six of eight resolved by rules alone, exactly, for free. The statistical layer
runs on two.

### Why stage 3 exists

A wrong mapping here is not a text-processing error — it is a **clinical** one.
Map `"Warf 5"` to Warfarin when it meant something else and you have silently
changed which DDI rules fire. **The statistical layer's uncertainty must not leak
into the decision path.**

And note what the low-confidence branch does: it **doesn't guess**. It says "I
don't know" and asks a human. That is 11.2's principle again — *a system that
cannot answer must say so, never return the answer that means safe.*

### ⚠️ Vocabulary correction: fuzzy matching ≠ embeddings

> *"Since it is new data we must use embedding..."*

Fuzzy string matching needs **no learned model at all**. Levenshtein distance or
a trigram index resolves `"Warf 5"` → `"Warfarin"` on pure character overlap.

| Method | Compares | Learned? | Use for |
|---|---|---|---|
| Levenshtein / trigram | **characters** | no | typos, abbreviations, salt forms |
| Embeddings (Ch 10.3) | **meaning** | yes | "blood thinner" → Warfarin |

> **Reach for the cheapest method that solves the problem. A learned model is
> not automatically the more powerful choice — it is the more expensive and less
> auditable one.**

**This is not "no ML in medicine."** It is: *learned models never sit on the path
where a wrong answer reaches a patient.* Same techniques, different blast radius.

## 6. Runnable file

```python
"""11.3 — hybrid drug-name resolution.
   Rules → statistics → rules. The gate never auto-accepts a guess."""

import re
import difflib
from dataclasses import dataclass
from typing import Optional

CANONICAL = ["warfarin", "aspirin", "metformin",
             "atenolol", "amlodipine", "atorvastatin"]

SALTS = ["sodium", "sod.", "sod", "hydrochloride",
         "hcl", "calcium", "potassium", "maleate"]


def normalise(raw: str) -> str:
    """STAGE 1 — deterministic. No model, no probability, no failure mode."""
    s = raw.lower().strip()
    s = re.sub(r'\b\d+\s*(mg|mcg|g|ml)\b', ' ', s)   # strip dose + unit
    s = re.sub(r'\b\d+\b', ' ', s)                    # strip bare numbers
    for salt in SALTS:
        s = s.replace(salt, ' ')
    s = re.sub(r'[^a-z ]', ' ', s)
    return re.sub(r'\s+', ' ', s).strip()


@dataclass
class MatchResult:
    raw: str
    canonical: Optional[str]
    method: str
    confidence: float
    action: str


def resolve(raw: str, threshold: float = 0.95) -> MatchResult:
    n = normalise(raw)

    # STAGE 1 — rules. Exact, free, covers the majority.
    if n in CANONICAL:
        return MatchResult(raw, n, "exact_rule", 1.0, "ACCEPT")

    # STAGE 2 — statistics, on the residual only.
    close = difflib.get_close_matches(n, CANONICAL, n=1, cutoff=0.6)
    if not close:
        return MatchResult(raw, None, "fuzzy", 0.0, "HUMAN_REVIEW")

    candidate = close[0]
    confidence = difflib.SequenceMatcher(None, n, candidate).ratio()

    # STAGE 3 — rules again. The gate. Uncertainty stops here.
    if confidence >= threshold:
        return MatchResult(raw, candidate, "fuzzy", round(confidence, 3), "ACCEPT")
    return MatchResult(raw, None, "fuzzy", round(confidence, 3), "HUMAN_REVIEW")


if __name__ == "__main__":
    tests = ["Warfarin", "WARFARIN SODIUM", "warfarin sod. 5mg", "Warf 5",
             "Metformin HCl 500mg", "aspirin 75",
             "Atorvastatin Calcium 20 mg", "Zolpidem"]

    for t in tests:
        r = resolve(t)
        print(f"{t:28} {r.method:11} conf={r.confidence:<6} "
              f"{r.action:13} {r.canonical}")
```

## 7. Never forget — carry these forward

1. **Symbolic = knowledge written by a human. Statistical = knowledge fitted from
   data.** Everything else about the two paradigms follows from that one line.

2. **The knowledge acquisition bottleneck killed expert systems** — but it
   *relocates* rather than disappears. Labelling data is expert time too, minus
   the readability.

3. **Separate facts from judgement.** Facts scale by ingestion (178k edges).
   Judgement stays small (~10 rules). MYCIN's error was baking the facts into
   the rules. This is the single most reusable idea in the chapter.

4. **Auto-updating logic destroys contestability.** A threshold that moves
   without a named human approving it cannot be cited, defended, or argued
   against.

5. **Rules → statistics → rules.** Deterministic work first, statistics only on
   what's left, then a rule-based gate on the output. Never let a probability
   flow straight into a decision.

6. **A learned model is not automatically the stronger tool.** Levenshtein beats
   embeddings for typos. Choose the cheapest method that solves it; every
   learned component costs auditability.

7. **One "severe / irreversible" outweighs every other row in the framework.**
   Blast radius dominates accuracy.

8. **Low confidence must route to a human, never to a guess.** Same rule as
   11.1's invalid payload and 11.2's dead database.

**The through-line of Chapter 11 so far:**

```
  11.1  bad data must fail LOUDLY at the boundary
  11.2  a broken dependency must fail LOUDLY at the rule
  11.3  an uncertain model must fail LOUDLY at the gate
        └── one principle, three layers:
            never let "I don't know" be rendered as an answer
```
