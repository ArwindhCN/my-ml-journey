## The core idea in one line

**A variable-length path lets the database find connections whose shape you
could not have written down — but the thing it finds is a hypothesis, not a
fact, and must never be presented as one.**

---

## 1. When the danger is not an edge

Simvastatin is metabolised by the CYP3A4 enzyme. Clarithromycin inhibits
CYP3A4. A patient on both accumulates simvastatin to dangerous levels —
rhabdomyolysis risk.

```
   (Simvastatin) ──METABOLISED_BY──► (CYP3A4) ◄──INHIBITS── (Clarithromycin)
```

**There is no `INTERACTS_WITH` edge between these two drugs.** DrugBank may
never have recorded one. The danger exists only as a *path* through the enzyme.

**Verified:**

```
  curated INTERACTS_WITH edges in the graph: [('Warfarin', 'Aspirin')]
  Simvastatin/Clarithromycin direct edge?    False
  path found (2 hops): Simvastatin -[METABOLISED_BY]- CYP3A4 -[INHIBITS]- Clarithromycin
```

A 12.4-style query handles this fine, because the shape is known:

```cypher
MATCH (a:Drug)-[:METABOLISED_BY]->(e:Enzyme)<-[:INHIBITS]-(b:Drug)
WHERE a.name = "Simvastatin" AND b.name = "Clarithromycin"
RETURN a.name, e.name, b.name
```

## 2. Why fixed-shape queries stop working

Contraindications also arrive through other chains:

```
  drug ──TREATS──► disease ──COMORBID_WITH──► disease ──CONTRAINDICATES──► drug
  drug ──TARGETS──► gene ──ASSOCIATED_WITH──► disease ──CONTRAINDICATES──► drug
  drug ──METABOLISED_BY──► enzyme ──ENCODED_BY──► gene ──HAS_VARIANT──► ...
```

Three hops, four hops, and you do not know in advance which shape connects any
two given drugs.

### ✅ The fatal problem: you must know the shape before writing the query

```
  fixed-shape queries answer:   "is Simvastatin connected to Clarithromycin
                                 via an enzyme?"          ← you named the shape

  what you actually need:       "is Simvastatin connected to Clarithromycin
                                 by ANY dangerous route?" ← shape unknown
```

**A fixed-shape query can only confirm what you already suspected.** But the
reason to build a graph at all was to find connections you had not anticipated.

The count is also hopeless. With 6 relationship types there are 6³ = **216**
distinct 3-hop shapes, and 1,296 at four hops. You cannot hand-write them, and
you would still miss the one that mattered.

### ❌ "A new relationship type should be merged"

`MERGE` creates-or-finds **data** (12.3). A new relationship type is not data you
merge — it is a new kind of edge appearing in the schema. Getting it into the
database is not the problem.

The problem is that all 216 hand-written queries were written *without* it, and
none will ever traverse it. **They do not break. They quietly stop being
complete** — no error, fewer results, no sign anything was missed. Chapter 11's
failure mode, again.

## 3. Variable-length paths

```cypher
MATCH path = (a:Drug {name: "Simvastatin"})-[*1..3]-(b:Drug {name: "Clarithromycin"})
RETURN path
```

`[*1..3]` means *"between one and three hops, of any relationship type, in any
direction."* You stop specifying the shape and let the database find it.

| Syntax | Meaning |
|---|---|
| `-[:INTERACTS_WITH]-` | exactly one hop, one named type |
| `-[*1..3]-` | 1 to 3 hops, **any** type |
| `-[:INHIBITS*1..3]-` | 1 to 3 hops, all of type `INHIBITS` |
| `-[:A\|B\|C*1..3]-` | 1 to 3 hops, any of types A, B or C |
| `-[*]-` | any length — **dangerous, see §4** |

`path` is itself a variable — the whole route, not just the endpoints:

```cypher
RETURN [n IN nodes(path) | n.name] AS route,
       [r IN relationships(path) | type(r)] AS steps,
       length(path) AS hops
```

That matters for **contestability** (11.2). A clinician told "these drugs are
risky" needs to know *why*, and the path **is** the explanation.

## 4. Path explosion

```cypher
MATCH path = (a:Drug {name: "Warfarin"})-[*1..5]-(b:Drug)
RETURN b.name
```

Warfarin has roughly 300 direct edges. Each of those nodes has its own, five
levels deep. **Each hop multiplies.**

**Verified — the theoretical cost at ~20 relevant edges per node:**

```
    depth 1:         20 paths
    depth 2:        400 paths
    depth 3:      8,000 paths
    depth 4:    160,000 paths
    depth 5:  3,200,000 paths        ← from ONE starting node
```

That is not "slow" — it is a query that may not return before the request times
out, holding memory throughout. `-[*]-` with no upper bound can exhaust the
heap.

It also revisits nodes. A path can run `Warfarin → CYP3A4 → Simvastatin →
CYP3A4 → …`. **Neo4j will not repeat a *relationship* within one path, but it
will happily repeat a *node*.**

### Four fixes, in order of importance

**1. Bound the depth — always.** Never write `-[*]-`. Clinically meaningful
chains are 2–4 hops; beyond that the "connection" is coincidence, because in a
dense biomedical graph almost everything reaches almost everything within six
hops.

**2. Restrict the relationship types.**

```cypher
MATCH path = (a:Drug {name:"Warfarin"})
             -[:METABOLISED_BY|INHIBITS|INDUCES*1..3]-
             (b:Drug)
```

The `|` means "any of these types." Cutting from 20 edges per node to 3 changes
depth-3 from 8,000 paths to 27 — **a 300× reduction from one line.**

**Verified on the sample graph:**

```
   depth |   ANY type |  pharma types only | reduction
  ----------------------------------------------------------
       1 |          3 |                  1 |      3.0x
       2 |         10 |                  4 |      2.5x
       3 |         20 |                  4 |      5.0x
       4 |         33 |                  4 |      8.2x
```

**3. Anchor both ends** — see §5.

**4. Use `shortestPath` when you want *the* route, not every route:**

```cypher
MATCH path = shortestPath(
  (a:Drug {name:"Simvastatin"})-[:METABOLISED_BY|INHIBITS*1..4]-(b:Drug {name:"Clarithromycin"})
)
RETURN [n IN nodes(path) | n.name] AS route
```

It stops at the first result instead of enumerating all of them.

### The survivable query

```cypher
MATCH path = (a:Drug {name: "Warfarin"})
             -[:METABOLISED_BY|INHIBITS|INDUCES*1..3]-
             (b:Drug)
WHERE b <> a
RETURN DISTINCT b.name, length(path) AS hops
ORDER BY hops
LIMIT 50
```

Bounded depth, restricted types, `DISTINCT` to collapse multiple routes to the
same drug, `LIMIT` as a backstop.

## 5. Type restriction is correctness, not just speed

This is the part that is easy to miss. Restricting types is usually described as
an optimisation. It is also a **correctness** requirement.

**Verified — all types allowed, 2 hops, Simvastatin → Clarithromycin:**

```
  3 path(s) found:
    Simvastatin -[APPROVED_IN]- USA -[APPROVED_IN]- Clarithromycin      ✗ MEANINGLESS
    Simvastatin -[MANUFACTURED_BY]- Pfizer -[MANUFACTURED_BY]- Clarithromycin  ✗ MEANINGLESS
    Simvastatin -[METABOLISED_BY]- CYP3A4 -[INHIBITS]- Clarithromycin   ✓ pharmacological
```

Two of the three are real graph paths and clinically absurd. Both drugs being
approved in the same country connects **every** drug to **every** other drug.
Sharing a manufacturer means nothing pharmacologically.

> **Restricting relationship types is how you encode what a *pharmacologically
> valid route* looks like.** Without it, "connected" degenerates into "exists in
> the same database."

## 6. Anchoring both ends — bidirectional search

A common confusion: *"the traversal starts from the drug, and there is one node
for the drug — how can it start from two different places?"*

**It is two anchors, not two starting points.** Both drugs are named in the
query, so *both ends of the path are known before the search begins*:

```cypher
MATCH path = (a:Drug {name: "Simvastatin"})-[*1..4]-(b:Drug {name: "Clarithromycin"})
              ▲                                       ▲
              └── pinned to one node                  └── also pinned to one node
```

Compare with the unanchored form, where only one end is known:

```cypher
MATCH path = (a:Drug {name: "Simvastatin"})-[*1..4]-(b:Drug)
                                                      ▲
                                                      └── ANY drug — free variable
```

### Why two anchors is dramatically cheaper

```
   Simvastatin ●───●───●            ●───●───● Clarithromycin
                        ╲          ╱
                         ╲        ╱
                          ● ── ● ●
                             ▲
                    the two searches meet here
```

**Verified cost model, 20 edges per node:**

```
    one anchor,  depth 4 :  160,000 paths
    two anchors, depth 2 :      800 paths   (200x cheaper)
```

Because each hop *multiplies*, halving the depth does not halve the cost — it
takes roughly the square root of it.

**Verified on the sample graph — the two frontiers and where they meet:**

```
  Simvastatin frontier   : 5 nodes
  Clarithromycin frontier: 5 nodes
  meeting points         : ['Atorvastatin', 'CYP3A4', 'Clarithromycin',
                            'Rifampicin', 'Simvastatin']
```

This is **bidirectional search**, and Neo4j's planner does it automatically when
both endpoints are pinned. You write nothing special — you simply have to *give*
it both endpoints. It is the same idea as meeting a friend halfway across
Chennai rather than one of you crossing the whole city.

## 7. A path is not an edge

The conceptual heart of 12.5.

```
   CURATED EDGE                        INFERRED PATH
   ────────────                        ─────────────
   (Warfarin)-[INTERACTS_WITH          Simvastatin -[METABOLISED_BY]-
     {severity:"HIGH",                   CYP3A4 -[INHIBITS]-
      source:"DrugBank v5.1"}]->         Clarithromycin
     (Aspirin)

   a pharmacologist established it     your traversal produced it
   severity set by a human             severity has no source
   false-positive rate: known          false-positive rate: unknown
   → a curated FACT                    → a HYPOTHESIS
```

For the curated edge the alert writes itself — the fields are stored on the
relationship:

```python
Finding(
    rule_id  = "DRUG_INTERACTION",
    severity = "HIGH",                    # read from r.severity
    evidence = "DrugBank DDI record",     # read from r.evidence
    source   = "DrugBank v5.1",           # read from r.source
)
```

For the inferred path there is no `r.severity` to read and no `r.source` to
cite. **Nobody wrote down "Simvastatin and Clarithromycin interact."** The
traversal produced that claim.

### ❌ "The source is Neo4j"

Neo4j is **where the facts are stored, not where they came from**. Citing Neo4j
is like a student citing "the library" instead of the book. Neo4j held the
DrugBank facts too — and for those you cite DrugBank, because DrugBank
established them.

### ✅ The honest Finding

```python
Finding(
    rule_id     = "INFERRED_INTERACTION",           # different rule_id
    severity    = "MODERATE",                       # NOT the curated HIGH
    explanation = "Simvastatin is metabolised by CYP3A4, which Clarithromycin "
                  "inhibits. Elevated simvastatin levels are possible.",
    evidence    = "Inferred from a 2-hop mechanistic path: "
                  "Simvastatin -[METABOLISED_BY]-> CYP3A4 <-[INHIBITS]- Clarithromycin",
    source      = "Inferred by BioPrecision-AI from DrugBank v5.1 edges "
                  "(no direct DDI record exists)",
    inferred    = True,                             # a flag the frontend renders
)
```

Three things this gets right:

**`source` names who inferred it and from what.** The underlying edges still come
from DrugBank; the *combination* is yours. Both are stated.

**`evidence` contains the actual path.** That is what makes it contestable
(11.2). A pharmacist can inspect `Simvastatin → CYP3A4 ← Clarithromycin` and
judge whether the mechanism is real at these doses. Nobody can argue with "the
graph said so."

**Lower severity and a different `rule_id`.** Present an inference identically to
a curated fact and you have quietly promoted a hypothesis.

### Why the ratio makes this urgent

**Verified on the sample graph:**

```
    curated pairs : 1
    inferred pairs: 9
    ratio: 9 inferred for every 1 curated
```

Inferred pairs vastly outnumber curated edges, and the gap widens as the graph
grows. Render them identically and the alert list fills with unvalidated
findings — the alert-fatigue problem from 12.4, at scale.

> **A traversal result is not the same epistemic object as a stored edge. Store
> the distinction, render it differently, and never let an inference occupy the
> same visual slot as a curated fact.**

### Where this lands

This is 11.3's two-path split, arriving from a new direction:

```
  curated edges          → clinical decision path    (rules, alerts)
  inferred paths         → research / review path    (flagged, lower priority)
  GNN link prediction    → research path             (Ch 14.8)
```

An inferred path is the **symbolic cousin of a GNN's predicted edge**. Both
propose something nobody wrote down. Both belong in front of a human before they
reach a clinician.

## 8. Runnable file

```python
"""12.5 — path explosion, type restriction, bidirectional search,
   and counting inferred pairs against curated ones."""

import itertools

EDGES = [
    ("Simvastatin",    "METABOLISED_BY",  "CYP3A4"),
    ("Clarithromycin", "INHIBITS",        "CYP3A4"),
    ("Atorvastatin",   "METABOLISED_BY",  "CYP3A4"),
    ("Rifampicin",     "INDUCES",         "CYP3A4"),
    ("Warfarin",       "METABOLISED_BY",  "CYP2C9"),
    ("Fluconazole",    "INHIBITS",        "CYP2C9"),
    ("Amiodarone",     "INHIBITS",        "CYP2C9"),
    ("Warfarin",       "INTERACTS_WITH",  "Aspirin"),      # a CURATED edge
    # edges that are real but pharmacologically meaningless
    ("Simvastatin",    "MANUFACTURED_BY", "Pfizer"),
    ("Clarithromycin", "MANUFACTURED_BY", "Pfizer"),
    ("Simvastatin",    "APPROVED_IN",     "USA"),
    ("Clarithromycin", "APPROVED_IN",     "USA"),
]

DRUGS = {"Simvastatin", "Clarithromycin", "Warfarin", "Fluconazole",
         "Amiodarone", "Rifampicin", "Atorvastatin", "Aspirin"}
PHARMA = {"METABOLISED_BY", "INHIBITS", "INDUCES"}

adj = {}
for s, t, e in EDGES:                       # undirected traversal
    adj.setdefault(s, []).append((t, e))
    adj.setdefault(e, []).append((t, s))


def paths(start, max_hops, types=None, target=None):
    """All simple paths up to max_hops. types=None means ANY type."""
    out, stack = [], [([start], [])]
    while stack:
        nodes, rels = stack.pop()
        if rels and (target is None or nodes[-1] == target):
            out.append((nodes, rels))
        if len(rels) >= max_hops:
            continue
        for t, nxt in adj.get(nodes[-1], []):
            if types and t not in types:
                continue
            if nxt in nodes:                # no node revisits
                continue
            stack.append((nodes + [nxt], rels + [t]))
    return out


def show(nodes, rels):
    return nodes[0] + "".join(f" -[{r}]- {n}"
                              for r, n in zip(rels, nodes[1:]))


# ── the danger that exists only as a path ────────────────────────
for n, r in paths("Simvastatin", 2, PHARMA, target="Clarithromycin"):
    print("found:", show(n, r))

# ── type restriction is CORRECTNESS ──────────────────────────────
print("\nall types allowed, 2 hops:")
for n, r in paths("Simvastatin", 2, target="Clarithromycin"):
    ok = all(x in PHARMA for x in r)
    print(f"  {show(n,r)}   {'OK' if ok else '<- MEANINGLESS'}")

# ── path explosion ───────────────────────────────────────────────
print("\ntheoretical cost, 20 edges per node:")
for d in range(1, 6):
    print(f"  depth {d}: {20**d:>10,} paths")
print(f"  one anchor depth 4 : {20**4:>8,}")
print(f"  two anchors depth 2: {2*20**2:>8,}   "
      f"({20**4 / (2*20**2):.0f}x cheaper)")

# ── inferred vs curated ──────────────────────────────────────────
curated = [(s, e) for s, t, e in EDGES if t == "INTERACTS_WITH"]
inferred = {(a, b) for a, b in itertools.combinations(sorted(DRUGS), 2)
            if not any({a, b} == {s, e} for s, e in curated)
            and paths(a, 2, PHARMA, target=b)}
print(f"\ncurated: {len(curated)}   inferred: {len(inferred)}   "
      f"ratio {len(inferred)//len(curated)}:1")
```

## 9. Never forget

1. **Some dangers exist only as paths.** No `INTERACTS_WITH` edge links
   Simvastatin and Clarithromycin; the risk lives in
   `METABOLISED_BY → CYP3A4 ← INHIBITS`.

2. **Fixed-shape queries require knowing the shape in advance** — which defeats
   the purpose of a graph. Six relationship types give 216 distinct 3-hop
   shapes.

3. **A new relationship type does not break your queries. It silently makes them
   incomplete.** ❌ Not a `MERGE` problem — a coverage problem.

4. **`[*1..3]` searches without specifying the shape.** `path` is a variable
   holding the whole route.

5. **Each hop multiplies.** 20 edges per node → 3.2 million paths at depth 5.
   **Never write `-[*]-` without an upper bound.**

6. **Neo4j won't repeat a relationship within a path, but it will repeat a
   node.** Loops through a hub enzyme are possible.

7. **Restricting relationship types is correctness, not just speed.**
   `APPROVED_IN → USA → APPROVED_IN` connects every drug to every other drug.
   Type restriction encodes what a *valid mechanism* looks like.

8. **Anchoring both ends enables bidirectional search.** Two anchors, not two
   starting points. Depth 4 one-sided (160,000) versus depth 2 from each side
   (800) — 200× cheaper, because halving depth takes the square root of cost.

9. **A traversal result is a hypothesis; a stored edge is a curated fact.**
   Different `rule_id`, lower `severity`, an `inferred: True` flag.

10. **❌ "Source: Neo4j" is wrong.** Neo4j is where facts are stored, not where
    they came from. Cite what the inference was built *from*, and say that you
    inferred it.

11. **Put the path itself in `evidence`.** That is what makes an inference
    contestable rather than an oracle.

12. **Inferred pairs vastly outnumber curated ones (9:1 even in a toy graph).**
    Rendering them identically buries the validated findings in unvalidated
    ones.
