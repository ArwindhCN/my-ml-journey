## 1. The model

Linear regression predicts a number as a weighted sum of features plus a bias:

```
ŷ = w₁·x₁ + w₂·x₂ + … + w_d·x_d + b
```

For Chennai flats: `ŷ (rent) = w_area · area + w_rooms · bedrooms + b`.

For many flats at once, we stack them into a matrix:

```
X : (n, d)   n flats, d features
w : (d,)     one weight per feature
ŷ = X @ w + b    → shape (n,)   one prediction per flat
```

The model is fixed. **Everything interesting is in the question: which w and b are "best"?** That needs a way to score a choice of weights — a **loss function**.

> 🧠 **Stop-and-think 1.** You have 500 flats with 3 features each. What shape is `X`? What shape is `w`? What shape is `X @ w`?
>
> *Your answer:*
>
> <details><summary>Answer</summary>
>
> `X` is (500, 3), `w` is (3,), `X @ w` is (500,) — one prediction per flat. The inner dimensions (3 and 3) must match; that's what "one weight per feature" means in shapes.
> </details>

## 2. Why not just add up the errors?

Error for one flat = `ŷ − y`. The obvious score is the sum of errors.

```
flat A:  +₹4,000   (too high)
flat B:  −₹4,000   (too low)
flat C:      ₹0
sum   =      ₹0
```

✅ *Session:* "Total is 0 — positive and negative errors cancel out."

The consequence: a disastrous model with errors of +₹1 lakh and −₹1 lakh **also** scores 0. The score can't tell perfect from terrible. **A loss must make every error count as bad, regardless of sign.**

Two ways to remove the sign:

```
MAE = mean of |error|     (absolute value)
MSE = mean of error²      (square)
```

Both fix the cancelling. The rest of this note is about **which one, and why** — the first *Why this, not that* of Stage 1.

## 3. How much attention does each loss give to a big error?

```
flat A:   ₹1,000
flat B:   ₹1,000
flat C:  ₹10,000
```

| | contributions | flat C's share |
|---|---|---|
| MAE | 1 + 1 + 10 = 12 | 10 / 12 ≈ **83%** |
| MSE | 1 + 1 + 100 = 102 | 100 / 102 ≈ **98%** |

Squaring makes MSE pour almost all of its attention into the biggest error.

❌ *Session:* "So it's a good thing only." — **Not only.** It depends on *why* the error is big:

- If flat C's rent is **real** and big errors are genuinely costly → MSE's focus is good.
- If flat C's rent is a **typo** (₹25,000 entered as ₹2,50,000) → MSE bends the whole line toward a fake point.

> 🧠 **Stop-and-think 2.** Under MSE, the model chases the typo flat. What happens to its predictions for all the *normal* flats?
>
> *Your answer:*
>
> <details><summary>Answer</summary>
>
> ✅ *Session:* "It shifts weights toward that flat, so normal flats are predicted too high." One bad row damages thousands of good predictions. This is **outlier sensitivity** — MSE's main weakness.
> </details>

## 4. The gradient: what gradient descent actually feels

Gradient descent doesn't see the loss — it sees the loss's **slope**. For one flat:

```
MSE:  loss = error²    →  gradient = 2 · error
MAE:  loss = |error|   →  gradient = +1 or −1     (only the sign; size ignored)
```

Near the end of training, errors are tiny (say ₹10):

- **MSE**: gradient = 2 × 10 = small → small steps → the model **glides into** the minimum. ✅ *Session:* "MSE gradient shrinks near the minimum, so steps get smaller."
- **MAE**: gradient is still ±1 → the **same-sized step forever** → overshoots, flips sign, overshoots back — **bounces around** the answer. Fix: shrink η over time (learning-rate schedules, M7.4).

MAE also has a sharp corner at error = 0 where the slope isn't defined.

❌ *Session:* "If we use MAE we must not proceed with gradient descent." — **Wrong.** At the corner PyTorch simply uses gradient 0, and `nn.L1Loss` trains fine. Its only real problem is the fixed step size, which η decay fixes.

> 🧠 **Stop-and-think 3.** Connect this to M0 Q1. There, the error got multiplied by `(1 − η·x²)` every step. Under MSE, why does a *shrinking* gradient near the minimum make gradient descent *settle* rather than bounce, as long as η is in the safe range?
>
> *Your answer:*
>
> <details><summary>Answer</summary>
>
> Step size = η × gradient, and the MSE gradient is proportional to the error. So each step removes a *fraction* of the remaining error — as the error shrinks, the step shrinks with it. With η in the safe range, that fraction is less than the whole error, so it never overshoots by more than it gains. MAE removes a *fixed amount* each step, which can't shrink to match a tiny remaining error.
> </details>

## 5. MSE leads to the mean, MAE leads to the median

*This was my biggest doubt in the session ("how can MSE 'predict' a mean?"), so it gets the full treatment.*

**Untangle the word first.** A loss doesn't predict anything — the **model** predicts. The loss is only the **scorecard** used during training. Training adjusts the model until its scorecard is as low as possible. "MSE leads to the mean" is shorthand for:

> If you train with MSE, the predictions the model ends up making are **averages**. Train with MAE, and they end up as **middle values (medians)**.

### 5.1 The simplest possible model

Forget features. The model can output only **one number, c**, for every flat. Rents (₹ thousands): **10, 20, 90**.

| c | MAE total (sum of distances) | MSE total (sum of squared distances) |
|---|---|---|
| 20 (median) | 10 + 0 + 70 = **80** ← lowest | 100 + 0 + 4900 = 5000 |
| 30 | 20 + 10 + 60 = 90 | 400 + 100 + 3600 = 4100 |
| 40 (mean) | 30 + 20 + 50 = 100 | 900 + 400 + 2500 = **3800** ← lowest |

### 5.2 Why each lands where it does — a tug of war

- **MAE: every flat pulls with equal strength**, no matter how far away. Move c right by ₹1 from 20: you get ₹1 closer to one flat (90) and ₹1 further from two (10, 20) → total gets worse. Balance = equal numbers of flats on each side = **median**. *How far* the 90 is doesn't matter — it's just "one flat on the right."
- **MSE: far flats pull harder** (pull strength = distance). The 90 pulls with 70, the 10 with only 10. Balance is where the pulls cancel: `(c − 10) + (c − 20) + (c − 90) = 0` → `c = 40` = **mean**.

**Analogy — one bus stop for three houses on a street.** Minimise total walking → put it at the middle house (median). Punish long walks extra hard → it shifts toward the far house (mean).

### 5.3 Watch training find it (verified run)

Nobody told the model "compute the mean." Gradient descent just lowered its score:

```python
import torch

rents = torch.tensor([10., 20., 90.])            # ₹ thousands
for name, loss_fn, lr in [("MSE", torch.nn.MSELoss(), 0.1),
                          ("MAE", torch.nn.L1Loss(),  0.5)]:
    c = torch.tensor(0.0, requires_grad=True)    # the whole model: one number
    opt = torch.optim.SGD([c], lr=lr)
    sched = torch.optim.lr_scheduler.StepLR(opt, step_size=100, gamma=0.5)  # shrink η over time
    for step in range(1, 601):
        opt.zero_grad()
        loss = loss_fn(c.expand(3), rents)       # predict c for every flat
        loss.backward()
        opt.step(); sched.step()
        if step in (1, 10, 50, 600):
            print(f"{name} step {step:3d}: c = {c.item():6.2f}")
```

```
MSE step   1: c =   8.00
MSE step  10: c =  35.71
MSE step  50: c =  40.00
MSE step 600: c =  40.00
MAE step   1: c =   0.50
MAE step  10: c =   5.00
MAE step  50: c =  15.17
MAE step 600: c =  20.00
```

### 5.4 With real features

Take every 1,200 sq ft, 2-bedroom flat in your data — their rents vary, say ₹18k–₹30k. An MSE-trained model predicts roughly **their average** for a new flat like that; an MAE-trained one predicts roughly **their middle value**.

**Choosing a loss = choosing what kind of "typical" your model outputs.** Rents are skewed (a few luxury flats pull the mean up), so "the typical rent" is often closer to the median.

## 6. Huber: the loss I invented before learning its name

Engineer's question from the session: *I want MSE's smooth, slowing gradient for small errors AND MAE's resistance to typos for big errors.*

✅ *Session:* "Use error² when small, |error| when it's above a threshold." — that's the **Huber loss**, with threshold **δ**:

```
            ⎧ ½·e²               if |e| ≤ δ     ← MSE-style (smooth, slows down)
Huber(e) =  ⎨
            ⎩ δ·(|e| − ½·δ)      if |e| > δ     ← MAE-style (straight line, robust)
```

The odd-looking `− ½·δ` stitches the two pieces so their **values and slopes match at δ** — no sudden jump in the gradient. Gradient: `e` when small, `δ · sign(e)` when large — so a huge error pulls with at most δ, never more.

PyTorch: `torch.nn.HuberLoss(delta=...)`. Choosing δ: roughly "the size of error I still consider normal noise."

## 7. The deep why: MSE is maximum likelihood under Gaussian noise

*Why MSE isn't an arbitrary convention. MML Ch 9 does this formally.*

**Assumption:** the true rent = the model's prediction + random noise, and the noise is bell-shaped (Gaussian) with spread σ:

```
y = ŷ + ε,     ε ~ Normal(0, σ²)
```

The probability density of seeing the actual rent y, given the model's ŷ, is:

```
p(y | ŷ) = 1/√(2πσ²) · exp( −(y − ŷ)² / (2σ²) )
```

**Maximum likelihood** = choose the weights that make the rents we actually observed *most probable*. With n independent flats, that probability is the product of the n densities. Products are awkward, so take the log (it turns products into sums and doesn't move the maximum):

```
log-likelihood = Σ [ −½·log(2πσ²)  −  (yᵢ − ŷᵢ)² / (2σ²) ]
                     └ constant ┘     └ the only part that depends on w ┘
```

Maximising this = **minimising Σ (yᵢ − ŷᵢ)²** — the sum of squared errors. The constant and the `2σ²` don't change *where* the best w is.

> 🧠 **Stop-and-think 5.** The derivation says: *if the noise is Gaussian, MSE is the right loss.* So what is MSE quietly assuming about your data — and which kind of data would break that assumption?
>
> *Your answer:*
>
> <details><summary>Answer</summary>
>
> It assumes errors are bell-shaped: small errors common, big errors **extremely** rare (the Gaussian tail drops off like e^(−e²)). Data with occasional large errors — typos, luxury flats, sensor glitches — has "heavy tails" and breaks it. That's exactly where MSE gets dragged. If you assume **Laplace** noise instead (density ∝ e^(−|e|), heavier tails), the same derivation gives **MAE**. **Your loss is your assumption about the noise.**
> </details>

**Numerical check (verified run)** — same rents 10, 20, 90, σ = 5. Gaussian negative log-likelihood and MSE bottom out at the same c:

```
c =   20   MSE =  1666.7   Gaussian NLL =  107.6
c =   30   MSE =  1366.7   Gaussian NLL =   89.6
c =   40   MSE =  1266.7   Gaussian NLL =   83.6   ← both lowest here
c =   50   MSE =  1366.7   Gaussian NLL =   89.6
```

## 8. Why this, not that — regression losses

| Option | Assumes about noise | Model outputs | Outliers | Gradient near the answer | Wins when | Fails when | PyTorch |
|---|---|---|---|---|---|---|---|
| **MSE** | Gaussian (thin tails) | conditional **mean** | dragged by them ❌ | shrinks → settles ✅ | data is clean; big errors truly costly; you want a closed-form solution (M1.2) | typos, heavy tails | `nn.MSELoss` |
| **MAE** | Laplace (heavier tails) | conditional **median** | robust ✅ | fixed ±1 → bounces without η decay | skewed targets; dirty data; "typical" = median | you need the mean; no η schedule | `nn.L1Loss` |
| **Huber** | Gaussian near the centre, heavy tails outside δ | between mean and median | robust beyond δ ✅ | shrinks inside δ ✅ | mostly clean data with some outliers | δ chosen badly (too large → MSE, too small → MAE) | `nn.HuberLoss(delta=…)` |

**Why MSE is the default:** smooth gradient that settles by itself, an exact closed-form solution for linear regression, and a probability justification (Section 7). Its price is outlier sensitivity.

**Two related things that are *not* different losses:**
- **RMSE** = √MSE. Same best weights as MSE (the square root doesn't move the minimum). Used for **reporting**, because it's in rupees, not rupees².
- **Cleaning outliers first** is right for genuine typos — but it can't replace a robust loss: you can't always tell a typo from a real ₹2.5 lakh Boat Club Road flat, and tomorrow's data arrives uncleaned.

## 9. Break it on purpose (verified run)

**Setup:** 20 normal flats (~₹20 per sq ft + noise) plus **one typo** (₹25k entered as ₹2,50,000). Fit a line with each loss; predict a normal 1,200 sq ft flat.

**My prediction (session):** ✅ MSE dragged most, Huber in the middle, MAE least.

```python
import torch
torch.manual_seed(0)
area = torch.linspace(500, 2000, 20)
rent = 0.02 * area + torch.randn(20) * 1.5       # ~₹20/sq ft + noise, in ₹ thousands
area = torch.cat([area, torch.tensor([1250.])])
rent = torch.cat([rent, torch.tensor([250.])])   # typo: ₹25k entered as ₹250k
x = (area - area.mean()) / area.std()            # standardized (M0 Q1!)

def fit(loss_fn, X, Y):
    w = torch.zeros(2, requires_grad=True)       # [slope, bias]
    opt = torch.optim.Adam([w], lr=0.5)
    sched = torch.optim.lr_scheduler.StepLR(opt, 500, 0.3)
    for _ in range(4000):
        opt.zero_grad()
        loss_fn(w[0] * X + w[1], Y).backward()
        opt.step(); sched.step()
    return w.detach()

q = (1200 - area.mean()) / area.std()            # a normal 1,200 sq ft flat
clean = fit(torch.nn.MSELoss(), x[:20], rent[:20])
print(f"clean MSE (no typo)   -> ₹{(clean[0]*q + clean[1]).item()*1000:,.0f}")
for name, fn in [("MSE", torch.nn.MSELoss()),
                 ("Huber d=5", torch.nn.HuberLoss(delta=5.0)),
                 ("MAE", torch.nn.L1Loss())]:
    w = fit(fn, x, rent)
    print(f"{name:9s} (with typo) -> ₹{(w[0]*q + w[1]).item()*1000:,.0f}")
```

```
clean MSE (no typo)   -> ₹24,424      ← the honest answer
MSE       (with typo) -> ₹35,113      ← dragged up ~₹10,700 by ONE row
Huber d=5 (with typo) -> ₹24,674      ← off by ~₹250
MAE       (with typo) -> ₹24,413      ← essentially unaffected
```

**The surprise:** Huber isn't halfway between MSE and MAE — it's nearly on top of MAE. (Explaining why is Checkpoint 1.)

## Never forget

1. **A loss must make every error bad, regardless of sign.** Raw sums cancel — a disaster can score 0.
2. **Squaring = obsession with the biggest error.** Good when big errors are real and costly; bad when they're typos.
3. **Gradient descent feels the slope, not the loss.** MSE's slope shrinks with the error, so it settles; MAE's is fixed at ±1, so it bounces unless η shrinks.
4. **The loss is a scorecard; the model makes the prediction.** Train with MSE → predictions are means. Train with MAE → medians. Choosing a loss is choosing *which "typical"* you want.
5. **Your loss is your assumption about the noise.** Gaussian → MSE. Laplace (heavier tails) → MAE. (MML Ch 9.)
6. **Huber = MSE inside δ, MAE outside.** δ is "the biggest error I still call normal noise."
7. **RMSE reports, MSE trains** — same minimum, different units.
8. **Cleaning data fixes known typos; a robust loss protects you from the ones you can't see.**
